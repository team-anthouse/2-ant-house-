## 🏗️ 인프라 아키텍처

외부 트래픽은 방화벽을 거쳐 웹 서버까지만 도달하고, 서버 간 통신은 WireGuard 내부망 위에서 허용된 조합만 통과합니다. DB·연동·로그 서버는 외부에서 어떤 경로로도 직접 도달할 수 없습니다.

```
                        인터넷 사용자
                            │  HTTPS (443)
                            ▼
              ┌──────────────────────────────┐
              │   OPNsense 게이트웨이          │  방화벽 + WireGuard 서버
              │   (포트포워딩 80/443/51820)   │  + 리버스 프록시
              └──────────────┬───────────────┘
                            │
                     ▼ DMZ (웹 서버)
              ┌──────────────────────────────┐
              │  Nginx + PHP-FPM + ModSecurity│  10.10.10.3
              └──────────────┬───────────────┘
                            │  WireGuard 내부망 (10.10.10.0/24)
      ┌──────────┬──────────┼──────────┬──────────┬──────────┐
      ▼          ▼          ▼          ▼          ▼          ▼
   DB 서버   KIS 연동    카카오 연동   구글 로그인   뉴스 연동   Graylog
 (10.10.10.2)(10.10.10.4)(10.10.10.6)(10.10.10.8)(10.10.10.7)(10.10.10.5)
   MariaDB    시세수집    소셜로그인   OAuth처리    뉴스수집   중앙로그수집
```

**핵심 설계**
- **3계층 구간 분리** — 외부망 / DMZ(웹) / 내부망(DB·연동·로그)
- **WireGuard VPN 오버레이** — 물리적으로 분산된 서버를 암호화 터널로 연결 (Hub & Spoke)
- **Deny-by-Default** — Any-to-Any 규칙 제거, 필요한 통신만 화이트리스트로 허용
- **포트포워딩 최소화** — 80/443/51820(VPN)만 개방, DB·연동 서버는 인터넷 라우팅 경로 자체가 없음

## 🔐 보안 정책

### 접근 제어 (방화벽)
- 방화벽 규칙을 5개 구간으로 분리 설계: 사용자→방화벽 / 방화벽→내부망 / 내부망↔내부망 / 관리망 / 로그망
- 외부→DMZ: 443/80만 허용, 그 외 차단
- DMZ→내부망: 웹서버→DB(3306), 웹서버→Graylog(1514/5044)만 허용
- 관리망: 관리자 VPN IP에서만 SSH(22) 허용
- WAN DDoS rate-limit — IP당 60초 300연결 초과 시 자동 차단

### 인증 · 세션
- 소셜 로그인 OAuth 핸드셰이크 방어: state 파라미터 검증, 1회용 ticket, `session_regenerate_id`로 세션 고정 공격 방지, redirect_uri 하드코딩으로 오픈 리다이렉트 차단
- 세션 쿠키: HttpOnly · SameSite=Lax · Secure(프록시 조건부)
- CSRF 토큰 검증 (매수/매도 등 상태 변경 요청)
- 관리자 SSH/GUI: 5회 실패 시 sshlockout 차단(자동 해제 없음), root 직접 로그인 차단

### DB 접근 권한 (최소권한)
- 서비스 계정별 DML 권한으로 축소 (ALL PRIVILEGES → SELECT/INSERT/UPDATE/DELETE)
- 미사용 레거시 계정·허깨비 권한 정리
- 서비스별 계정 분리 (webapp / stock / auth_service)

### 데이터 보호
- 전 트래픽 HTTPS 강제, HSTS·`server_tokens off` 보안 헤더
- API 시크릿(카카오·KIS·네이버·구글)은 `.env` 환경변수로 분리, nginx에서 `.env` 외부 접근 403 차단
- 거래내역 CSV 내보내기: 수식 인젝션 방지(`=+-@` 앞 `'` 삽입), 본인 데이터만 조회

### 로그 · 관제
- 중앙 로그 수집(Graylog): nginx access/error, ModSecurity audit, 앱 로그, Suricata IDS, SSH 인증 로그
- Graylog 대시보드로 서버별 SSH 로그인 실패 모니터링 → 외부 스캔봇의 무차별 대입 시도 탐지

## 🛡️ 실제 공격 시뮬레이션 및 방어 검증

범용 체크리스트가 아니라, 개미집이 실제로 가진 기능을 겨냥해 공격을 재현하고 결과를 기록했습니다.

| # | 공격 | 시나리오 | 결과 |
|---|---|---|---|
| 1 | **CSRF** | 세션 쿠키 유지한 채 CSRF 토큰만 위조해 매수 주문 POST | 주문 거부, 보유수량 변동 없음 ✅ |
| 2 | **Brute Force** | 관리자 SSH에 비밀번호 반복 대입 | 5회 초과 시 IP 차단(무응답) ✅ |
| 3 | **Race Condition** | 1주 보유 상태에서 매도 2건 동시 전송 | 1건 체결·1건 거부, 음수 잔고 없음(행 잠금) ✅ |
| 4 | **IDOR** | 내 세션으로 타 사용자 주문 취소 시도 | 소유자 불일치로 미처리 ✅ |
| 5 | **CSV Injection** | 거래내역 내보내기 수식 삽입 | `csvSafe()`로 무력화 ✅ |
| 6 | **SQL Injection** | 검색 파라미터 인젝션 | PDO Prepared Statement로 원천 차단 ✅ |
| 7 | **미인증 스트림** | 로그인 없이 실시간 시세 스트림 접근 | nginx `auth_request`로 401 ✅ |
| 8 | **WAF (SQLi/XSS)** | `search.php`에 SQLi·XSS 요청 | ModSecurity + OWASP CRS로 HTTP 403 차단 ✅ |

> **8번의 발견:** 점검 중 ModSecurity가 `DetectionOnly`(탐지만, 차단 안 함) 모드였던 것을 발견 → `SecRuleEngine On` 전환 후 정상 트래픽 회귀 테스트를 거쳐 실제 차단 확인. "설치했다"와 "막고 있다"는 다르다는 것을 실증한 사례.

### 방화벽 차단 테스트 (룰셋 검증)
관리자 PC(WireGuard 연결)에서 각 서버의 미인가 포트로 접속을 시도해, 방화벽 로그에서 `block / Default deny`를 전 구간 확인.

| 서버 | 테스트 포트 | 결과 |
|---|---|---|
| 웹서버 / DB / KIS / 카카오 / 구글 / 뉴스 / Graylog | 미인가 포트 | 전부 차단 확인 ✅ |
| OPNsense 관리 GUI | 관리자 허용 경로 | 정상 접속 ✅ |
