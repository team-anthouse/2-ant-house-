## 🏗️ 인프라 아키텍처

외부 트래픽은 방화벽을 거쳐 웹 서버까지만 도달하고, 서버 간 통신은 WireGuard 내부망 위에서 허용된 조합만 통과합니다. DB·API·로그 서버는 외부에서 어떤 경로로도 직접 도달할 수 없습니다.

```
인터넷 사용자
   │  HTTPS
   ▼
OPNsense 게이트웨이  (방화벽 + WireGuard 서버 + 리버스 프록시)
   │
   ▼
웹 서버 (DMZ)  ── Nginx + PHP-FPM
   │  WireGuard 내부망
   ├── DB 서버        (웹서버에서만 접근)
   ├── API/시세 서버
   └── 로그 서버      (중앙 로그 수집)
```

- **3계층 구간 분리** — 외부망 / DMZ(웹) / 내부망(DB·API·로그)
- **WireGuard VPN** — 물리적으로 분산된 서버를 암호화 터널로 연결 (Hub & Spoke)
- **Deny-by-Default** — Any-to-Any 규칙 제거, 필요한 통신만 화이트리스트로 허용

## 🔧 피준원 담당 — 인프라·네트워크 & 웹 서버

### 네트워크 · 방화벽
- 총 8대 서버의 전체 네트워크 아키텍처와 방화벽 NAT/ACL 설계
- OPNsense 방화벽 + WireGuard VPN 게이트웨이 직접 구축
- Zero Trust 화이트리스트 룰셋을 5개 구간(사용자→방화벽 / 방화벽→내부망 / 내부망↔내부망 / 관리망 / 로그망)으로 분리 설계·적용
- WAN 구간 DDoS rate-limit — IP당 60초 300연결 초과 시 자동 차단 (운영 중 실제 차단 확인)
- 관리망 화이트리스트 — 관리자 고정 IP에서만 SSH·방화벽 관리 접근 허용

### 웹 서버
- Nginx + PHP-FPM 기반 웹 서버(Ubuntu) 직접 구축 및 HTTPS 운영
- 리버스 프록시 뒤 실제 클라이언트 IP 복원, 보안 헤더 적용

### 검증
- 규칙표를 근거로 삼지 않고, 외부망에서 각 서버로 직접 접근을 시도해 **Default Deny 정책이 실제로 차단하는지 전 구간 검증**
