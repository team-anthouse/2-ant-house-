## 🐜 개미집 — 실시간 시세부터 매매까지

**개미집**은 실시간 시세·호가·차트를 제공하는 모의투자 웹 서비스입니다. 사용자는 실제 주식 시장 데이터로 가상 매매를 경험할 수 있습니다.

| 기능 분류 | 세부 기능 |
|---|---|
| 계정 | 카카오·구글 소셜 로그인 (OAuth 2.0) |
| 거래 | 매수/매도 (지정가·시장가), 체결/미체결(PENDING) 관리 |
| 시세 | 실시간 시세·차트·호가 (SSE 스트림 + 한국투자증권 KIS Open API) |
| 기타 | 관심종목, 거래내역, GridStack 커스텀 대시보드, 뉴스 연동 |

---

## 🔎 왜 개미집인가?

금융 서비스는 사용자의 자산과 거래를 다루는 만큼, 인프라 보안이 서비스의 신뢰와 직결됩니다.

우리는 문서상의 보안 정책에 그치지 않고, **실제로 서비스되는 인프라를 직접 세우고, 적용한 방어가 정말 동작하는지 공격을 재현해 확인**하는 것을 목표로 삼았습니다. "설치했다"와 "막고 있다"는 다른 말이기 때문입니다.

---

## 🛡️ 우리가 구축한 인프라 구조

외부 트래픽은 방화벽을 거쳐 웹 서버까지만 도달하고, 서버 간 통신은 WireGuard 내부망 위에서 허용된 조합만 통과합니다. DB·연동·로그 서버는 외부에서 어떤 경로로도 직접 도달할 수 없습니다.

```
                        인터넷 사용자
                            │  HTTPS (443)
                            ▼
              ┌──────────────────────────────┐
              │   OPNsense 게이트웨이          │  방화벽 + WireGuard 서버
              │   (포트포워딩 80/443/51820)   │  + 리버스 프록시
              └──────────────┬───────────────┘
                            │
                     ▼ DMZ (웹 서버)
              ┌──────────────────────────────┐
              │  Nginx + PHP-FPM + ModSecurity│  10.10.10.3
              └──────────────┬───────────────┘
                            │  WireGuard 내부망 (10.10.10.0/24)
      ┌──────────┬──────────┼──────────┬──────────┬──────────┐
      ▼          ▼          ▼          ▼          ▼          ▼
   DB 서버   KIS 연동    카카오 연동   구글 로그인   뉴스 연동   Graylog
 (10.10.10.2)(10.10.10.4)(10.10.10.6)(10.10.10.8)(10.10.10.7)(10.10.10.5)
   MariaDB    시세수집    소셜로그인   OAuth처리    뉴스수집   중앙로그수집
```

- **3계층 구간 분리** — 외부망 / DMZ(웹) / 내부망(DB·연동·로그)
- **WireGuard VPN 오버레이** — 물리적으로 분산된 서버를 암호화 터널로 연결 (Hub & Spoke)
- **Deny-by-Default** — Any-to-Any 규칙 제거, 필요한 통신만 화이트리스트로 허용
- **포트포워딩 최소화** — 80/443/51820(VPN)만 개방, DB·연동 서버는 인터넷 라우팅 경로 자체가 없음

## 🔐 주요 보안 설계

| 영역 | 설계 내용 |
|---|---|
| **접근 제어** | 방화벽 규칙을 5개 구간(사용자→방화벽 / 방화벽→내부망 / 내부망↔내부망 / 관리망 / 로그망)으로 분리. 외부→DMZ는 443/80만 허용, WAN DDoS rate-limit(IP당 60초 300연결 초과 시 자동 차단) |
| **인증 · 세션** | OAuth 핸드셰이크 방어(state 검증·1회용 ticket·세션 재발급·리다이렉트 고정), CSRF 토큰 검증, 세션 쿠키 HttpOnly·SameSite·Secure |
| **DB 최소권한** | 서비스 계정별 DML 권한으로 축소, 미사용 계정·허깨비 권한 정리, 계정 분리 |
| **데이터 보호** | 전 트래픽 HTTPS 강제, API 시크릿 `.env` 분리 + 외부 접근 403 차단, CSV 수식 인젝션 방지 |
| **로그 · 관제** | Graylog 중앙 로그 수집(nginx·WAF·Suricata·SSH 인증), 대시보드로 무차별 대입 시도 탐지 |

## ⚠️ 실제 공격 시뮬레이션 & 방어 검증

범용 체크리스트가 아니라, 개미집이 실제로 가진 기능을 겨냥해 공격을 재현하고 결과를 기록했습니다.

| # | 공격 | 시나리오 | 결과 |
|---|---|---|---|
| 1 | **CSRF** | 세션 쿠키 유지한 채 CSRF 토큰만 위조해 매수 주문 POST | 주문 거부, 보유수량 변동 없음 ✅ |
| 2 | **Brute Force** | 관리자 SSH에 비밀번호 반복 대입 | 5회 초과 시 IP 차단(무응답) ✅ |
| 3 | **Race Condition** | 1주 보유 상태에서 매도 2건 동시 전송 | 1건 체결·1건 거부, 음수 잔고 없음(행 잠금) ✅ |
| 4 | **IDOR** | 내 세션으로 타 사용자 주문 취소 시도 | 소유자 불일치로 미처리 ✅ |
| 5 | **CSV Injection** | 거래내역 내보내기 수식 삽입 | `csvSafe()`로 무력화 ✅ |
| 6 | **SQL Injection** | 검색 파라미터 인젝션 | PDO Prepared Statement로 원천 차단 ✅ |
| 7 | **Unauth Stream** | 로그인 없이 실시간 시세 스트림 접근 | nginx `auth_request`로 401 ✅ |
| 8 | **WAF (SQLi/XSS)** | `search.php`에 SQLi·XSS 요청 | ModSecurity + OWASP CRS로 HTTP 403 차단 ✅ |

> **8번의 발견:** 점검 중 ModSecurity가 `DetectionOnly`(탐지만, 차단 안 함) 모드였던 것을 발견 → `SecRuleEngine On` 전환 후 정상 트래픽 회귀 테스트를 거쳐 실제 차단 확인.

**방화벽 차단 테스트** — 관리자 PC에서 각 서버의 미인가 포트로 접속을 시도해, 방화벽 로그에서 `Default deny`를 전 구간 확인 ✅
